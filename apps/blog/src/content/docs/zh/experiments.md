---
title: 实验
description: 检验一项改动是否改善了某个指标。用功能开关拆分访客，选择主要指标，查看提升幅度和胜过 control 的概率，然后发布胜出的变体。
---

实验会在你选定的指标（例如注册数或每位用户的收入）上，比较 [功能开关](/docs/zh/feature-flags) 的各个变体。Flareboard 统计谁看到了哪个变体，衡量每组之后做了什么，并在某个变体明显更好时，或者该继续等待时告诉你。

## 开始之前

- **套餐：** 与功能开关一样，实验需要 Cloud 或 Business 套餐。在 Free 套餐上，API 会返回 `403` 和“Experiments require a paid plan.”。自托管安装拥有全部功能，没有套餐限制。
- **角色：** 你需要一个可以编辑该网站的账号。只有查看权限的账号可以阅读结果。
- **一个能拆分访客的开关。** 请先创建它，并确保它会把一部分访客分到 `control`（见 [设置开关](#设置开关)）。
- **曝光。** 你的代码必须在改动出现的页面上，用 `getFeatureFlag`、`isFeatureEnabled` 或 `useFeatureFlag` 读取开关。见 [在浏览器中读取开关](/docs/zh/feature-flags#2-在浏览器中读取开关)。
- **一个目标事件。** 指标需要一个你追踪的事件，例如 `signup_completed`。见 [追踪事件](/docs/zh/events)。

## 设置开关

实验把开关提供的每个变体与 `control` 做比较。

- 开关必须提供 `control`：添加一个名为 `control` 的变体，或者让变体权重之和小于 100，剩下的就归 `control`。如果开关完全不提供 `control`，结果会显示 **修正设置**，并给出警告 **缺少 control 对照组**。
- 没有变体的开关也可以：在放量范围内的访客看到 `test`，其他人看到 `control`。两组都会记录曝光，因为每次读取开关都会被记录。
- 如果你在服务端用 PostHog SDK 读取开关，请给开关显式的变体，其中包括一个名为 `control` 的变体。响应为 `false` 或空的曝光不会被算作一个组，所以布尔开关简单的开和关取值不会提供对照组。
- 用 [identify()](/docs/zh/events#识别用户) 识别你的用户。Flareboard 按 distinct ID 统计用户，对匿名访客则退回到会话 ID，所以匿名访客在之后的访问中可能被再次统计。

## 1. 创建实验

1. 打开你的网站，然后在侧边栏中打开 **实验**。
2. 点击 **创建实验**。
3. 填写表单并点击 **创建实验**。新实验以草稿状态开始。

| 字段 | 作用 |
| --- | --- |
| **名称** | 必填，最长 120 个字符。 |
| **功能开关** | 把用户拆分到各个变体的开关。字段下方会显示它的变体和权重。 |
| **假设** | 你要测试的是什么改动。可选，最长 500 个字符。 |
| **主要指标** | 决定实验结果的指标。 |
| **次要指标** | 最多五个需要关注的护栏指标和副作用。点击 **添加次要指标**。 |
| **最小可检测效应（%）** | 值得检测的最小相对提升，从 0.1 到 100，默认 10。它决定计划的样本量。 |

每个指标有一个 **衡量方式**、一个 **事件**，有时还有一个 **数值属性**。

| **衡量方式** | 每位用户的贡献 |
| --- | --- |
| **转化（是否触发事件）** | 用户在被曝光之后触发过该事件则为 1，否则为 0。结果显示为比率。 |
| **每位用户的次数** | 用户触发该事件的次数。结果显示为平均值。 |
| **每位用户的属性合计** | 用户所有事件上某个数值事件属性之和，没有事件则为 0。 |
| **属性平均值** | 用户所有事件上某个数值事件属性的平均值。只有至少触发过一次事件的用户才被计入。 |

事件名称最长 80 个字符。属性必须是该事件的数值属性。

## 2. 启动实验

打开实验并点击 **开始**。实验变为 **运行中**，分析窗口在这一刻开启。启动实验不会改变开关，开关必须处于启用并在提供结果的状态。

| 状态 | 含义 |
| --- | --- |
| **草稿** | 尚未开始。结果预览的是实验创建以来的曝光。 |
| **运行中** | 窗口从你第一次点击 **开始** 时开启，一直延续到现在。 |
| **已暂停** | 点击 **暂停** 来标记。窗口仍然延续到现在，开关继续提供结果。 |
| **已完成** | 点击 **完成** 来关闭窗口。此后结果覆盖固定的窗口。再次点击 **开始** 会重新打开它，窗口又会延续到现在。 |

## 3. 曝光和指标是如何统计的

- **单位：** 会话有 distinct ID 时用用户的 distinct ID，否则用会话 ID。
- **曝光：** 一个单位在窗口内第一次出现该实验开关的 `$feature_flag_called` 事件时，被算作已曝光。它属于第一次曝光时的变体。
- **指标事件：** 当同一个单位在其第一次曝光时或之后、并且在窗口结束之前触发某个事件，这个事件才会被计入。
- **被排除的用户：** 被曝光到多个变体的单位，会被排除在所有指标之外。页面会告诉你有多少个。
- **分组：** 每一种不同的开关响应都算作一个组，空响应和 `false` 除外。`control` 是基准。

## 4. 阅读结果

打开实验。每次打开页面时，结果都会根据你的事件重新计算。

顶部的提示框给出决策：

| 决策 | 何时 |
| --- | --- |
| **暂无数据** | 窗口内没有曝光。 |
| **修正设置** | 没有对照组，或者流量分配与开关不一致（**流量分配与开关配置不符**，即样本比例不匹配）。在相信任何数字之前，请先修正它。 |
| **继续收集** | 数据还不足以下结论。 |
| **发布变体** | 每个组至少有 30 个用户（转化指标还要求总共至少 10 次转化），并且有一个变体在统计上显著地胜过 control。 |
| **保留原版** | 已达到最小样本，并且要么在达到计划样本量时仍没有胜出者，要么每个变体都显著差于 control。 |

提示框下方：

- **用户** 是被分析的用户数，以及每个变体的占比。
- **提升** 是领先变体相对于 control 的相对变化。
- **胜过 control 的概率** 是各变体中优于 control 的最高概率。高于 99.9% 的值显示为“>99.9%”。
- **计划样本进度** 显示你离检测到你的最小可检测效应所需的每个变体用户数还有多近，以及按当前流量大约还剩几天。这个估算使用 95% 置信度和 80% 检验力。
- **每日结果** 按天（UTC）绘制主要指标或新用户。至少有两天的数据后才会出现。

每个指标有一张表，每个变体一行。用 **频率学派** 和 **贝叶斯** 在两种方法之间切换。

| 列 | 显示内容 |
| --- | --- |
| **分组** | 变体键。`control` 是基准。 |
| **用户** | 该组的用户数。对属性平均值来说，是 **有数值的用户**。 |
| **转化率** | 指标值。对次数，标签是 **每位用户平均**；对合计，是 **每位用户**；对平均值，是 **平均值**。转化还会显示已转化数除以总用户数。 |
| **相对 control 提升** | 相对于 control 的相对变化。 |
| **95% 区间** | 提升的区间。使用 **贝叶斯** 时，该列是 **95% 可信区间**。 |
| **显著性** | **显著** 或 **不显著**，并附带 p 值。使用 **贝叶斯** 时，该列是 **胜过 control 的概率**。 |

频率学派方法使用 95% 置信度的双侧检验：转化用 z 检验，均值用 Welch t 检验。贝叶斯方法给出每个变体胜过 control 的后验概率，以及 95% 可信区间。

**最近样本** 列出最近被曝光的用户及其变体、页面和是否已转化，并附有每个会话的链接。

## 5. 发布胜出者

当决策是 **发布变体** 时，点击 **应用胜出变体**。然后 Flareboard 会：

- 把胜出的变体设为 100%，其他变体设为 0%；
- 把每个条件组的放量设为 100%，并清除变体覆盖；
- 启用该开关；
- 把实验标记为 **已完成**。

这次更改会在开关的 **变更历史** 中显示为 **已发布实验胜出变体**。如果开关没有变体，它会得到一个 100% 的胜出变体。没有明确的胜出者时，API 会返回 `400` 和“Experiment does not have a significant winning variant.”。

你也可以手动结束实验：自己编辑开关，然后点击 **完成**。在实验被删除之前，实验所使用的开关不能被删除。

## 使用 API

所有端点都在 `https://api.flareboard.dev/api/websites/YOUR_WEBSITE_ID` 下。自托管用户使用自己的 API 地址。发送 `Authorization: Bearer YOUR_API_KEY`。读取需要带 **读取** 权限的密钥，写入需要 **写入** 权限。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `GET` | `/experiments` | 列出实验。 |
| `POST` | `/experiments` | 创建一个。 |
| `GET` | `/experiments/EXPERIMENT_ID` | 获取一个。 |
| `PATCH` | `/experiments/EXPERIMENT_ID` | 更新字段，或把 `status` 设为 `draft`、`running`、`paused` 或 `completed`。 |
| `DELETE` | `/experiments/EXPERIMENT_ID` | 删除它。 |
| `GET` | `/experiments/EXPERIMENT_ID/results` | 包含变体、指标、指引和决策的结果。 |
| `POST` | `/experiments/EXPERIMENT_ID/apply` | 发布胜出的变体。 |

用一个请求创建并启动实验：

```bash
curl -X POST https://api.flareboard.dev/api/websites/YOUR_WEBSITE_ID/experiments \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Checkout redesign",
    "featureFlagId": "YOUR_FLAG_ID",
    "primaryMetric": { "type": "conversion", "event": "purchase_completed" },
    "secondaryMetrics": [{ "type": "property_sum", "event": "purchase_completed", "property": "amount" }],
    "minimumDetectableEffect": 10,
    "status": "running"
  }'
```

指标的 `type` 是 `conversion`、`count`、`property_sum` 或 `property_mean`。后两种需要 `property`。返回 `201`，内容是该实验。[MCP 服务](/docs/zh/mcp) 的 AI 工具可以通过 `list_experiments` 列出实验及其结果。

## 检查是否生效

1. 启动实验。
2. 打开你的网站，让页面读取开关，然后执行会触发目标事件的操作。
3. 等一分钟，然后刷新实验页面。**用户** 大于 0，**最近样本** 列出你的这次访问；如果你之后触发了目标事件，**已转化** 会显示为 **是**。

## 故障排查

| 现象 | 原因与处理 |
| --- | --- |
| **暂无数据** | 窗口内没有收到 `$feature_flag_called` 事件。请用 `getFeatureFlag` 或 `isFeatureEnabled` 读取开关，而不是只用 `getFeatureFlagPayload`。在开关的 **概览** 标签页中检查曝光。 |
| **缺少 control 对照组** | 开关没有提供 `control`。添加一个名为 `control` 的变体，或降低变体权重，让剩下的归 `control`。 |
| **流量分配与开关配置不符** | 用户没有按配置的比例拆分。请检查定向规则、缓存、重定向，或测试期间对开关所做的更改。 |
| 有些用户被排除 | 他们被曝光到多个变体，例如测试期间开关被修改过。实验运行期间请避免修改开关。 |
| 编辑开关之后数字变了 | 每次打开页面时，结果都会根据目前已记录的曝光重新计算。流量分配检查是与你点击 **开始** 时开关的分配比例相比较的。 |
| 缺少 **应用胜出变体** | 决策不是 **发布变体**，实验已经完成，或者你的账号只有查看权限。 |
